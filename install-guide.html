항목내용
PCWindows 10 / 11. 관리자 권한이 있으면 편해요.
Claude 구독Claude Pro 또는 Max 요금제예요. 회사에서 Team/Enterprise를 쓰면 그 계정도 돼요. API 키로도 쓸 수 있어요.

ADT가 켜져 있는지 확인하는 법 SAP GUI에서 SICF를 실행해요. /sap/bc/adt 서비스가 활성 상태면 돼요. 권한이 없으면 Basis 담당자에게 요청하세요.
회사 SAP 서버에 처음 연결한다면 아래 B1~B4를 Basis 담당자에게 먼저 요청하세요. 특히 B1 웹 포트가 열려야 나머지를 시험할 수 있어요. 설치(DEV 서버)는 한 번만 하고, QA·PRD 서버에는 트랜스포트로 반영해요.

B1BC 웹 포트 열기 — 가장 먼저

sc4sap은 SAP 서버의 웹(HTTP/HTTPS) 포트로 접속해요. SAP GUI 포트(32xx)나 RFC 포트(33xx)는 쓰지 않아요. 이 포트가 막혀 있으면 B2 이후를 다 해 둬도 접속 시험을 할 수 없어요.

포트 번호 규칙

SAP 포트는 보통 앞자리 + 인스턴스 번호예요. 아래 예시는 인스턴스 번호가 00인 서버예요.

용도규칙예시 (인스턴스 00)
SAP GUI32 + 번호3200
RFC33 + 번호3300
웹 HTTP — sc4sap이 씀80 + 번호8000
웹 HTTPS — sc4sap이 씀443 + 번호44300
규칙과 다른 번호를 쓰는 서버도 있어요실제 번호는 아래 1단계에서 확인해요.

여는 순서

단계누가할 일확인 방법
1BC서버에 웹 포트가 있는지 확인해요.
SMICM → 이동 → 서비스		HTTP(또는 HTTPS) 행에 포트 번호가 있고 활성 상태예요.
2BC없으면 포트를 추가해요.
RZ10에서 icm/server_port_<n> = PROT=HTTP,PORT=8000 → ICM 재시작		1단계 화면에 새 행이 보여요.
3BC · 네트워크 담당방화벽에서 개발자 PC → 서버 IP·웹 포트를 허용해요.—

웹 포트를 열 수 없을 때 — RFC(NCo) 방식

웹 포트 대신 RFC 포트(33 + 인스턴스 번호)로 접속하는 방식이에요. 개발자 PC의 SAP .NET Connector(NCo)를 써요.

항목웹 포트 방식NCo 방식
포트웹 80NN / 443NNRFC 33NN
ICF 노드 (B2)필요필요 없음
Gateway 서비스 등록 (B5)필요필요 없음
S_SERVICE필요필요 없음
S_ADT_RES필요똑같이 필요 — RFC로 들어와도 ADT가 검사해요
S_RFCADT용 + Z 함수같음 + SADT_REST (RFC로 ADT 호출)
Z 함수 설치·이송DEV 설치 → QA 이송같음
개발자 PC제한 없음Windows + NCo 설치
NCo는 사용자마다 직접 설치해야 해요 NCo(SAP Connector for Microsoft .NET 3.1)는 SAP 라이선스 프로그램이라 sc4sap이 대신 배포할 수 없어요. SAP Support Portal(Software Downloads)에서 받고, 다운로드 권한이 있는 S-user 계정이 필요해요. S-user가 없으면 회사 Basis 담당자에게 설치 파일이나 설치를 요청하세요. SAP GUI와 함께 이미 설치된 PC도 있어요.
그 밖의 제약내용
Windows PC만Mac·Linux에서는 쓸 수 없어요. 이런 PC는 웹 포트 방식만 돼요.
서버 직접 접속만앱 서버 주소 + 인스턴스 번호로만 접속해요. 메시지 서버(로그온 그룹), SAProuter, SNC는 지원하지 않아요.
암호화SNC를 쓰지 않아서 RFC 통신이 암호화되지 않아요. 사내망에서만 쓰세요. Basis 담당자와 확인하세요.
Z 함수 버전ZMCP_ADT_DISPATCH에 NCo용 기능(FM_PROXY)이 있어야 해요. 최신 소스로 설치하면 들어 있어요.
권한은 줄지 않음S_ADT_RES와 조회·개발 권한은 웹 포트 방식과 같아요. 줄어드는 건 ICF·Gateway·S_SERVICE뿐이에요.

1PowerShell 실행 권한 열기

Windows는 기본으로 PowerShell 스크립트 실행을 막아 둬요. 이걸 열지 않으면 Claude Code 설치와 claude, npm 명령이 오류로 멈춰요.

① PowerShell 열기

  1. 키보드에서 Win 키를 누르고 "PowerShell"을 입력해요.
  2. Windows PowerShell을 클릭해요.
  3. 관리자 권한으로 열려면 오른쪽 클릭 후 관리자 권한으로 실행을 눌러요.

② 현재 설정 확인

PowerShellGet-ExecutionPolicy -List

CurrentUser와 LocalMachine이 둘 다 Undefined나 Restricted면 막혀 있는 상태예요.

③ 권한 열기 — 둘 중 하나를 실행해요

방법 A — 내 계정만 (관리자 권한 필요 없음, 권장)

PowerShell (일반)Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned

방법 B — PC 전체 (관리자 권한 PowerShell에서)

PowerShell (관리자)Set-ExecutionPolicy -Scope LocalMachine -ExecutionPolicy RemoteSigned

확인 질문이 나오면 Y(또는 A)를 입력하고 Enter를 눌러요.

④ 다시 확인

PowerShellGet-ExecutionPolicy
성공하면RemoteSigned가 나와요.
RemoteSigned가 뭔가요? 내 PC에서 만든 스크립트는 실행하고, 인터넷에서 받은 스크립트는 서명된 것만 실행해요. 개발자 PC에서 흔히 쓰는 설정이에요.
"그룹 정책에 의해 재정의되었습니다" 오류가 나오면 회사가 정책으로 막아 둔 상태예요. 직접 바꿀 수 없어요. IT 부서에 "PowerShell 실행 정책 RemoteSigned 허용"을 요청하세요.

2Git 설치

Claude Code와 sc4sap이 내부에서 Git을 써요. Windows에서는 꼭 필요해요.

  1. git-scm.com/download/win에서 설치 파일을 받아요.
  2. 설치 화면은 모두 기본값으로 두고 Next만 눌러요.
  3. 설치가 끝나면 새 PowerShell 창을 열고 아래 명령으로 확인해요.
PowerShellgit --version
성공하면git version 2.xx.x 같은 글자가 나와요.

3Node.js 설치

sc4sap의 SAP 연결 서버(MCP)가 Node.js로 돌아가요. 버전 20 이상이 필요해요.

  1. nodejs.org에서 LTS 버전을 받아요.
  2. 설치 화면은 기본값 그대로 진행해요.
  3. 열려 있던 PowerShell 창은 닫아요. 새 창을 열어 확인해요.
PowerShellnode --version npm --version
성공하면v20 이상의 숫자가 나와요. 예: v22.11.0

4Claude Code 설치

Claude Code는 터미널에서 쓰는 Claude예요. sc4sap은 그 위에 얹는 플러그인이에요.

방법 A — 공식 설치 스크립트 (권장)

PowerShellirm https://claude.ai/install.ps1 | iex

방법 B — npm으로 설치

방법 A가 회사망에서 막히면 이 방법을 써요.

PowerShellnpm install -g @anthropic-ai/claude-code

설치가 끝나면 PowerShell 창을 닫고 새로 열어요. 그다음 확인해요.

PowerShellclaude --version
성공하면버전 번호가 나와요.
"claude는 인식되지 않습니다"가 나오면 PowerShell 창을 다시 열어 보세요. 그래도 안 되면 PC를 재시작해요.

5로그인

처음 실행하면 로그인 화면이 나와요.

PowerShellclaude
  1. 테마(색상)를 고르라고 나와요. 방향키로 고르고 Enter를 눌러요.
  2. 로그인 방식에서 Claude account with subscription을 골라요. API 키를 쓰면 Anthropic Console을 골라요.
  3. 브라우저가 열려요. Claude 계정으로 로그인하고 승인을 눌러요.
  4. 터미널로 돌아오면 입력창(>)이 보여요.
잘 됐는지 확인입력창에 안녕이라고 써 보세요. 대답이 오면 성공이에요.
나가는 법/exit를 입력하거나 Ctrl + C를 두 번 눌러요.

6작업 폴더 만들기

sc4sap은 실행한 폴더에 작업 기록을 저장해요. 전용 폴더를 하나 만들어 두세요.

PowerShellmkdir $HOME\Documents\sap-work cd $HOME\Documents\sap-work claude
앞으로는 항상 이렇게 시작해요 PowerShell을 열고 cd $HOME\Documents\sap-work 다음에 claude를 실행해요.
폴더를 신뢰하겠냐고 물으면 Yes, proceed를 골라요. 내 작업 폴더라서 괜찮아요.

7sc4sap 플러그인 설치

이제부터는 Claude Code 입력창(>)에 입력해요. PowerShell 명령이 아니에요.

① 마켓플레이스 등록

Claude Code 입력창/plugin marketplace add https://github.com/babamba2/superclaude-for-sap.git

② 플러그인 설치

Claude Code 입력창/plugin install sc4sap

설치 범위를 물으면 User(모든 폴더에서 사용)를 고르면 편해요.

③ Claude Code 다시 시작

  1. /exit로 나가요.
  2. 같은 폴더에서 claude를 다시 실행해요.
설치 확인입력창에 /sc4sap까지만 입력해 보세요. /sc4sap:setup 같은 목록이 뜨면 성공이에요.

8SAP 연결 설정

Claude Code 입력창/sc4sap:setup

RFC 백엔드모르면 기본값(soap)을 그대로 써요.
ABAP 유틸 객체 설치DEV에서만 물어봐요. 트랜스포트 요청 번호가 필요할 수 있어요.
SPRO 추출 / 커스터마이징 인벤토리처음에는 N을 눌러 건너뛰어도 돼요. 나중에 따로 실행할 수 있어요.
권한 승인 창이 뜨면 Claude가 파일을 쓰거나 명령을 실행할 때 허락을 구해요. 설정 중에는 Yes를 골라도 돼요.
중간에 "MCP 재연결"을 하라고 하면 입력창에 /mcp를 입력해요. 목록에서 sap 서버를 골라 Reconnect를 눌러요.

B5개발자 Gateway 서비스 등록

OData 경로를 쓰려면 ZMCP_ADT_SRV 서비스를 등록해야 해요. 백엔드(/IWBEP)와 프런트엔드(/IWFND) 두 곳 모두 등록해야 동작해요. 웹 포트 대신 NCo 방식(B1)을 쓰면 이 단계는 필요 없어요.

시작 전 확인

  • /sc4sap:setup(8단계)으로 아래 객체가 준비돼 있어야 해요.
    • SEGW 프로젝트 ZMCP_ADT — 유형 "Service with SAP Annotations". setup 중에 SAP GUI에서 직접 만들어요.
    • 클래스 ZCL_ZMCP_ADT_MPC_EXT, ZCL_ZMCP_ADT_DPC_EXT — setup이 소스를 넣고 활성화해요.
    • 함수 ZMCP_ADT_DISPATCH, ZMCP_ADT_TEXTPOOL — RFC 가능 상태여야 해요. setup이 안내하면 SE37에서 "원격 호출 가능"을 체크해요.
  • B2의 /default_host/sap/opu/odata 노드가 켜져 있어야 해요.
  • B3의 Gateway 등록 권한이 있어야 해요.

입력할 값

필드값
서비스 이름 · 외부 서비스 이름ZMCP_ADT_SRV
모델 이름ZMCP_ADT_MDL
버전0001
네임스페이스비워 둠
모델 제공 클래스ZCL_ZMCP_ADT_MPC_EXT
데이터 제공 클래스ZCL_ZMCP_ADT_DPC_EXT
시스템 별칭LOCAL (같은 서버 안에서 호출, RFC 대상 NONE)
패키지클래스와 같은 패키지 또는 $TMP

등록 순서

  1. 백엔드 등록 — /IWBEP/REG_SERVICE → 등록 → 위 값 입력 → 저장
  2. 프런트엔드 등록 — /IWFND/MAINT_SERVICE → 서비스 추가 → 시스템 별칭 LOCAL, 외부 서비스 이름 ZMCP_ADT_SRV → 서비스 가져오기 → 선택한 서비스 추가 → 패키지 지정
  3. ICF 노드 활성화 — SICF → /default_host/sap/opu/odata/sap/ZMCP_ADT_SRV → 서비스 활성화
  4. 캐시 정리 — /IWFND/CACHE_CLEANUP → 모델 캐시 정리 → 실행
대안 경로/IWBEP/SB 권한이 있으면 1단계 대신 SEGW를 써도 돼요. SEGW에서 ZMCP_ADT 열기 → 런타임 객체 생성(F6) → 활성화 → 서비스 등록(시스템 별칭 LOCAL). 그다음 2~4단계는 똑같이 해요.

등록 확인

브라우저에서 아래 주소를 열어요.

브라우저https://sapdev.example.com:44300/sap/opu/odata/sap/ZMCP_ADT_SRV/$metadata?sap-client=100
  • <edmx:Edmx>로 시작하는 XML이 나오면 정상이에요.
  • XML 안에 FunctionImport Name="Dispatch"와 ComplexType Name="DispatchResult"가 있어야 해요.

문제 해결

증상원인조치
$metadata가 404ICF 노드가 꺼져 있거나 프런트엔드 등록이 빠짐등록 순서 3단계(SICF), 2단계(서비스 추가)
$metadata는 200인데 호출하면 500백엔드(/IWBEP) 등록이 빠짐 (/IWFND/MAINT_SERVICE의 백엔드 서비스 탭이 비어 있음)1단계 실행 → 프런트엔드 서비스 삭제 후 다시 추가
등록 후에도 500예전 모델 캐시가 남아 있음/IWFND/CACHE_CLEANUP 실행, ZMCP_ADT_FLUSH_CACHE를 P_FLUSH로 실행
원인을 모르는 500ABAP 예외가 OData 오류에 가려짐응답의 트랜잭션 ID로 /IWFND/ERROR_LOG 확인, ZMCP_ADT_FLUSH_CACHE를 P_DIAG로 실행
401인증 실패계정·비밀번호 확인, 초기 비밀번호 상태인지 확인
비상용 옵션ZMCP_ADT_FLUSH_CACHE의 P_REG는 백엔드 테이블에 직접 값을 넣어요. 일부 값이 빠질 수 있으니, 위 순서로 등록할 수 있으면 쓰지 마세요.
