Super-Claude for SAP 홈으로

사용 가이드

설치 가이드(CLI)

Claude Code 세션 안에서 마켓플레이스를 추가하고, 설정 위저드를 한 번 돌리면 끝납니다. MCP 서버는 위저드가 알아서 설치합니다

전체 원문 문서

요구사항

Node.js
20.0.0 이상
Claude Code
CLI 설치 완료 (Max·Pro 구독 또는 API 키)
SAP 시스템
ECC 6.0 · S/4HANA On-Premise · S/4HANA Cloud (Public·Private), ADT 활성화

MCP 서버 abap-mcp-adt-powerup 는 /sc4sap:setup 중 자동으로 설치·설정됩니다. 미리 받아둘 필요가 없습니다

설치

sc4sap 은 아직 공식 Claude Code 플러그인 마켓플레이스에 등록되어 있지 않습니다. 당분간은 저장소를 커스텀 마켓플레이스로 추가한 뒤 설치하세요

권장

커스텀 마켓플레이스로 추가

Claude Code 세션 안에서 두 줄을 차례로 실행합니다

/plugin marketplace add https://github.com/babamba2/superclaude-for-sap.git
/plugin install sc4sap

업데이트할 때

/plugin marketplace update babamba2/superclaude-for-sap
/plugin install sc4sap
대안

소스에서 설치

클론 후 빌드하고, Claude Code에서 /plugin marketplace add <로컬-경로> 로 해당 디렉터리를 가리킵니다

git clone https://github.com/babamba2/superclaude-for-sap.git
cd superclaude-for-sap
npm install && npm run build

설정 위저드

위저드는 한 번에 한 질문만 합니다. 기존 값이 있으면 보여주고 Enter로 유지할 수 있습니다

/sc4sap:setup
  1. 01

    시스템과 업종

    S4 또는 ECC 선택, ABAP 릴리즈 입력, 15개 업종 메뉴에서 선택. 이 값이 SPRO 테이블·BAPI·TCode와 ABAP 문법 게이팅을 결정합니다

  2. 02

    MCP 서버 설치

    abap-mcp-adt-powerup 을 <PLUGIN_ROOT>/vendor/abap-mcp-adt/ 에 클론하고 빌드합니다. 이미 있으면 건너뜁니다

  3. 03

    프로필 생성과 연결

    alias(KR-DEV 형식 권장)와 tier(DEV·QA·PRD)를 정한 뒤 URL·클라이언트·인증 방식·계정·언어를 하나씩 받습니다. RFC 백엔드는 soap · native · gateway · odata · zrfc 중 선택합니다

  4. 04

    연결 검증

    /mcp 로 재연결한 뒤 GetSession 왕복, 시스템 정보 확인, GetInactiveObjects 로 ADT 권한까지 확인합니다. Claude Code 재시작은 필요 없습니다

  5. 05

    ABAP 유틸 객체 생성

    DEV 프로필에서만 설치됩니다. ZMCP_ADT_UTILS 함수그룹과 ZIF_S4SAP_CM · ZCL_S4SAP_CM_* ALV 핸들러를 만듭니다. QA·PRD 에서는 거부하고 CTS 이관 안내를 출력합니다

  6. 06

    권한 훅 설치 required

    이 단계 없이는 설정이 완료되지 않습니다. block-forbidden-tables.mjs(행 추출 차단)와 tier-readonly-guard.mjs(tier 변이 차단)를 .claude/settings.json 에 등록하고 양쪽 스모크 테스트를 실행합니다

선택 단계

  • SPRO 설정 추출 - 토큰을 많이 쓰지만 캐시가 이후 작업의 토큰 사용을 크게 줄입니다
  • 커스터마이징 인벤토리 - Z*·Y* 확장과 어펜드 구조를 스캔합니다
  • HUD 상태 줄 - 재시작 후 활성 프로필과 tier, 토큰 사용량을 표시합니다

서브커맨드

/sc4sap:setup                # 전체 위저드
/sc4sap:setup doctor         # 상태 점검으로 라우팅
/sc4sap:setup mcp            # MCP 설정으로 라우팅
/sc4sap:setup spro           # SPRO 설정 추출만
/sc4sap:setup customizations # Z*/Y* 인벤토리만

멀티 프로필

한 Claude Code 세션에서 여러 SAP 연결을 다룹니다. 연결 하나가 프로필 하나이고, 프로젝트에는 어느 프로필이 활성인지만 기록됩니다

~/.sc4sap/                      저장소 간 공유
└── profiles/
    ├── KR-DEV/  sap.env · config.json
    ├── KR-QA/   sap.env · config.json
    └── KR-PRD/  sap.env · config.json

<project>/.sc4sap/              프로젝트 범위
├── active-profile.txt          "KR-DEV"
└── work/
    ├── KR-DEV/  program · cbo · ...
    └── KR-PRD/  ...
  • tier 는 읽기전용 강제의 기준입니다 QA·PRD 프로필에서는 Create* · Update* · Delete* 가 훅과 MCP 서버 두 층에서 차단됩니다
  • tier 는 변경할 수 없습니다 바꾸려면 프로필을 지우고 다시 만들어야 합니다
  • 비밀번호는 OS 키체인에 저장됩니다 Windows 자격 증명 관리자 · macOS 키체인 · Linux libsecret. 키체인을 못 쓰는 환경에서는 프로필 env 평문으로 대체하고 경고를 띄웁니다

3중 방어

운영계에 붙이기 전에 가장 먼저 검토되는 부분입니다. 문서가 아니라 코드로 강제됩니다

L1a

행 추출 차단

Claude Code PreToolUse 훅. 프로필의 blocklistProfile 을 기준으로 민감 테이블의 GetTableContents · GetSqlQuery 를 거부합니다

L1b

tier 변이 차단

Claude Code PreToolUse 훅. 매 호출마다 활성 프로필의 SAP_TIER 를 다시 읽어 QA·PRD 의 변경을 막습니다. 상태를 들고 있지 않습니다

L2

MCP 서버 자체 가드

우회할 수 없는 층입니다. 훅이 빠지거나 잘못 설정되어도 abap-mcp-adt-powerup 내부 가드가 항상 동작합니다

L1 훅은 IO·파싱 오류 시 통과시키고, L2 MCP 가드는 항상 켜져 있습니다. 권장 기본값은 L1a strict, MCP 서버 블록리스트 standard 입니다
