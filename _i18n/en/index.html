Functional/Technical Spec: ZMMR00020

Purpose in one line

A report that retrieves the change history of purchase order (PO) items (old/new values per field, change reason, changed by/at) for audit purposes

Object typeABAP Report (Executable Program), Include structure (T/S/A/O/I/F)
PackageZMMPAEK
ArchetypeSelection screen → Query → ALV Grid (docking container) display report

1. Business context

This program is an audit report that tracks the change history of purchase order data. It lets buyers and internal control/audit staff see which fields on a given PO, or in a given period, were changed by whom, when, and for what reason.

2. Data model

TableAccessKey fieldsNotes
ZMMT00120REBELN, EBELP, SEQ_NOCustom PO change-log table. Holds old/new values, reason, changed by, changed at
EKKOREBELNJoined only to get the vendor (LIFNR) from the PO header
LFA1RLIFNRVendor name (NAME1) lookup, one SELECT SINGLE per row inside the loop

3. Inputs & screens

FieldTypeRequiredDescription
S_EBELNSELECT-OPTIONS (EBELN)OptionalPO number range
S_EBELPSELECT-OPTIONS (EBELP)OptionalPO item number range
S_CHDATESELECT-OPTIONS (DATS)OptionalChange date range
P_FIELDPARAMETERS (CHAR 30)OptionalChanged field name pattern (wildcard match)

4. Main logic

  1. The user enters PO number, PO item, change date, and field name criteria on the selection screen.
  2. START-OF-SELECTION calls the data retrieval FORM.
  3. The change history is read with an INNER JOIN of ZMMT00120 and EKKO on PO number.

02Data readZMMT00120
03Vendor joinLFA1
04ALV displayScreen 0100

    ZMMR00020 — Code review

    An ALV report that shows the change history of purchase order items. It reads the change-log table ZMMT00120 and adds vendor details from EKKO and LFA1. The structure is simple, but there is one spot that slows down as the row count grows.

    Object ZMMR00020 · Review scope Full · Quality score 6/10 · Findings 1 high, 2 medium, 1 low

    Highest-impact fix — Replace the SELECT SINGLE inside the LOOP with a bulk read outside it.
