# sc4_redesign

배포 중인 루트 `index.html` 은 그대로 두고, 이 폴더에서 리디자인을 진행합니다.
로컬 확인: 이 폴더 상위(`SC4SAP HOMEPAGE`)에서 정적 서버를 띄운 뒤
`http://localhost:PORT/sc4_redesign/` 로 접속하세요. 파비콘을 `../assets/` 로
참조하므로 이 폴더만 단독으로 서빙하면 파비콘이 깨집니다.

```
python -m http.server 8080
```

리포트, 5시트 워크북)과 페이지의 생김새를 일치시켰습니다.

다크 모드는 같은 종이 비유를 밤에 옮긴 것입니다. 웜 니어블랙 `#171613`,

### 액센트를 두 단계로 나눈 이유

앰버는 아이보리 위에서 **2.85:1** 입니다. 텍스트 AA(4.5:1)에도, 의미 있는
아이콘 기준(3:1)에도 못 미칩니다. 그래서 채도가 필요한 곳(채움·마크·테두리·
그래픽)에는 `--accent` 를, 읽어야 하는 곳(텍스트·아이콘)에는 같은 색상을
어둡게 깎은 `--accent-text` (5.6:1)를 씁니다. 다크 모드에서는 앰버가 밝아져
8.8:1 이므로 두 값이 같습니다.

색을 바꾸려면 `css/tokens.css` 의 액센트 5줄만 고치면 됩니다. 직전 네이비
값은 바로 위 주석에 남겨 두었습니다.

### 서체 구성

본문과 모노는 IBM Plex. 엔지니어링과 엔터프라이즈 문서를 위해 그려진 서체이고
한국어·일본어 컷이 같은 패밀리로 존재해 세 언어가 하나로 조판됩니다.
(기존 사이트는 6종을 섞고 있었습니다.)

제목만 Schibsted Grotesk 로 분리했습니다. Plex Sans 는 본문용이라 큰 사이즈에서
표정이 없었고, Schibsted 는 신문·보도용으로 그려져 조임새가 좁고 헤드라인이
단단합니다. 한글·일본어 자소가 없으므로 CJK 는 Plex 컷으로 떨어지고, 한 줄 안에서
두 서체가 만납니다 (`SAP` / `Claude Code` 만 Schibsted).

`.t-display` 의 행간은 1.12 입니다. 라틴 기준으로 잡았던 1.04 는 한글·일본어
글자가 em 박스에서 더 깊이 앉아 클립 창에 잘렸습니다.

| CTA 도트 | 커서 주변 448px 창에만 도트가 보임. 창은 transform 으로 이동, 안쪽 도트는 역이동해 제자리 유지 (라이트 전용) |

전부 transform / opacity 로만 돌고 `prefers-reduced-motion` 에서 정지합니다.
Why 섹션의 좌측 열은 opacity 가 아니라 잉크 단계로 물러납니다. 투명도를 낮추면
대비가 4.5:1 아래로 떨어지기 때문입니다.

언어 전환은 `.shell` 만 페이드합니다. 섹션 배경·대시 구분선·히어로 앰비언트는
`.shell` 바깥에 있고 네비는 `.nav-inner` 라서, 방금 누른 컨트롤은 깜빡이지 않고
`aria-pressed` 와 썸은 클릭 즉시 반응합니다. 페이드 중 다른 언어를 누르면
무시하지 않고 대상만 바꿉니다.

테마 전환은 `.theme-swap` 클래스를 **스왑 동안에만** 걸고 380ms 뒤에 뗍니다.
`*` 에 트랜지션을 상시로 걸면 이후 내내 네비 호버 700ms, 리빌 620ms 같은
값들과 충돌합니다. 첫 페인트에는 걸지 않습니다 (`<head>` 인라인 스크립트가
이미 테마를 정해둔 상태라, 거기서 이징하면 전환이 아니라 깜빡임이 됩니다).

모바일 메뉴는 `display` 를 토글하지 않습니다. `display` 는 트랜지션이 안 되므로
`opacity` + `transform` 으로 움직이고 `visibility` 가 "없음"을 담당합니다.
열 때는 즉시, 닫을 때는 페이드가 끝난 뒤 전환되어 숨은 링크가 탭 순서에
남지 않습니다. 햄버거는 X 로 회전하며 교차 페이드하고, 두 글리프는
`grid-area: 1 / 1` 로 한 칸을 공유합니다.

### 헤드라인이 넘치던 문제

4.25rem 은 세 언어 모두에서 히어로 열을 넘겼습니다. `Your whole SAP system,`
가 약 714px, `SAP システム全体を` 가 전각 8자라 비슷한 폭을 요구하는데 열은
650px 입니다. 그래서 마지막 조각만 다음 줄로 떨어졌습니다.

`--fs-display` 상한을 **3.4rem** 으로 통일하고 히어로 좌측 열을 `1.15fr → 1.25fr`
로 넓혔습니다. 언어별 크기 분기는 필요 없어져 제거했고, `text-wrap: balance`
(남은 줄바꿈을 고르게 나눔)와 한국어 `word-break: keep-all` (어절 유지)만
안전장치로 남겼습니다.

현재 여유 (데스크톱 1240px 기준, 열 650px):

```
KO  443 / 470px      EN  569 / 470px      JP  480 / 470px
```

### Why 섹션 커넥터

세로 점선을 없애고 3열(`1fr auto 1fr`)로 바꿔 가운데에 커넥터를 넣었습니다.
점선이 배지의 세로 중앙을 가로질러 지나가고, 배지가 그 위를 덮습니다.

| z | 요소 |
|---|---|
| 0 | 점선 (배지 뒤를 그대로 통과) |
| 1 | 글로우 링 |
| 2 | 배지 (불투명, 뒤의 점선을 가림) |

글로우 링은 배지의 **자식이 아니라 형제**입니다. 음수 `z-index` 자식은 부모의
배경보다 위에 그려지기 때문에, 배지 안에 두면 아이콘 위로 번집니다.

점선은 `background-position` 이 아니라 대시 1주기(11px)만큼 `translateX` 로
움직입니다. 이음매가 없고 합성 단계에서만 처리됩니다. 모바일에서는 transform
회전 없이 그라디언트 축만 바꿔 세로로 서고, 여전히 배지를 통과합니다.

세로 정렬은 두 열이 `align-items: start` 로 위를 맞추고(두 h3 베이스라인 일치),
커넥터는 `align-self: center` 로 행 높이 중앙에 섭니다.

가로 위치는 왼쪽으로 살짝 치우쳐 있습니다. 제목·리드·두 리스트가 전부 왼쪽
정렬이라, 눈이 읽는 중심이 실제 중앙보다 왼쪽에 있기 때문입니다.

이 오프셋은 **트랜스폼이 아니라 트랙 비율**로 넣습니다 (`--link-bias: 1.16fr`,
오른쪽 열을 그만큼 넓힘). 처음엔 `translateX(-34px)` 로 했는데, 고정 픽셀은
주변이 전부 스케일되는 동안 혼자 크기를 유지해서 **창 폭을 바꾸면 중앙이
틀어졌습니다.** 비율로 바꾸면 어떤 폭에서든 열 영역의 일정 비율만큼 밀립니다.

```
viewport   열 영역   shift   비율
    900      657     24px   3.70%
   1024      748     28px   3.70%
   1280      894     33px   3.70%
   1920      884     33px   3.70%
```

더/덜 밀고 싶으면 `--link-bias` 하나만 조절하면 됩니다 (`1fr` = 정중앙).

오른쪽 열(`SC4SAP를 붙이면`)은 `--after-inset: 5%` 만큼 안쪽으로 더 들어가
커넥터에서 조금 떨어져 섭니다. 퍼센트라 트랙 폭에 대해 해석되므로 이것도
폭이 바뀌어도 비율이 유지됩니다 (1280에서 24px, 900에서 18px). 세로로 쌓이는
820px 이하에서는 좌우 개념이 없어 0 으로 떨어집니다.
