Super-Claude for SAP ホーム

利用ガイド

インストールガイド(CLI)

Claude Code のセッション内でマーケットプレイスを追加し、設定ウィザードを一度実行すれば完了です。MCP サーバーはウィザードが自動でインストールします

原文ドキュメント全文

動作要件

Node.js
20.0.0 以上
Claude Code
CLI インストール済み(Max・Pro サブスクリプションまたは API キー)
SAP システム
ECC 6.0 · S/4HANA On-Premise · S/4HANA Cloud (Public·Private)、ADT 有効化済み

MCP サーバー abap-mcp-adt-powerup は /sc4sap:setup の実行中に自動でインストール・設定されます。事前にダウンロードしておく必要はありません

インストール

sc4sap はまだ公式の Claude Code プラグインマーケットプレイスに登録されていません。当面は、リポジトリをカスタムマーケットプレイスとして追加してからインストールしてください

推奨

カスタムマーケットプレイスとして追加

Claude Code のセッション内で 2 行を順に実行します

/plugin marketplace add https://github.com/babamba2/superclaude-for-sap.git
/plugin install sc4sap

アップデートするとき

/plugin marketplace update babamba2/superclaude-for-sap
/plugin install sc4sap
代替

ソースからインストール

クローンしてビルドした後、Claude Code で /plugin marketplace add <ローカルパス> を使ってそのディレクトリを指定します

git clone https://github.com/babamba2/superclaude-for-sap.git
cd superclaude-for-sap
npm install && npm run build

設定ウィザード

ウィザードは一度に 1 つずつ質問します。既存の値があれば表示され、Enter でそのまま維持できます

/sc4sap:setup
  1. 01

    システムと業種

    S4 か ECC を選び、ABAP リリースを入力し、15 業種のメニューから選択します。これらの値によって SPRO テーブル・BAPI・TCode と ABAP 構文のゲーティングが決まります

  2. 02

    MCP サーバーのインストール

    abap-mcp-adt-powerup を <PLUGIN_ROOT>/vendor/abap-mcp-adt/ にクローンしてビルドします。すでにある場合はスキップします

  3. 03

    プロファイルの作成と接続

    alias(KR-DEV 形式を推奨)と tier(DEV・QA・PRD)を決めた後、URL・クライアント・認証方式・アカウント・言語を 1 つずつ入力します。RFC バックエンドは soap · native · gateway · odata · zrfc から選択します

  4. 04

    接続の検証

    /mcp で再接続した後、GetSession の往復、システム情報の確認、GetInactiveObjects による ADT 権限の確認まで行います。Claude Code の再起動は不要です

  5. 05

    ABAP ユーティリティオブジェクトの作成

    DEV プロファイルでのみインストールされます。ZMCP_ADT_UTILS 汎用モジュールグループと ZIF_S4SAP_CM · ZCL_S4SAP_CM_* ALV ハンドラを作成します。QA・PRD では拒否し、CTS 移送の案内を出力します

  6. 06

    権限フックのインストール required

    このステップなしでは設定は完了しません。block-forbidden-tables.mjs(行抽出のブロック)と tier-readonly-guard.mjs(tier による変更のブロック)を .claude/settings.json に登録し、両方のスモークテストを実行します

任意のステップ

  • SPRO 設定の抽出 - トークンを多く使いますが、キャッシュによって以降の作業のトークン使用量が大きく減ります
  • カスタマイズインベントリ - Z*・Y* の拡張とアペンド構造をスキャンします
  • HUD ステータスライン - 再起動後、アクティブなプロファイルと tier、トークン使用量を表示します

サブコマンド

/sc4sap:setup                # ウィザード全体
/sc4sap:setup doctor         # 状態チェックへルーティング
/sc4sap:setup mcp            # MCP 設定へルーティング
/sc4sap:setup spro           # SPRO 設定の抽出のみ
/sc4sap:setup customizations # Z*/Y* インベントリのみ

マルチプロファイル

1 つの Claude Code セッションで複数の SAP 接続を扱えます。1 つの接続が 1 つのプロファイルで、プロジェクトにはどのプロファイルがアクティブかだけが記録されます

~/.sc4sap/                      リポジトリ間で共有
└── profiles/
    ├── KR-DEV/  sap.env · config.json
    ├── KR-QA/   sap.env · config.json
    └── KR-PRD/  sap.env · config.json

<project>/.sc4sap/              プロジェクト単位
├── active-profile.txt          "KR-DEV"
└── work/
    ├── KR-DEV/  program · cbo · ...
    └── KR-PRD/  ...
  • tier は読み取り専用を強制する基準です QA・PRD プロファイルでは、Create* · Update* · Delete* がフックと MCP サーバーの 2 層でブロックされます
  • tier は変更できません 変更するには、プロファイルを削除して作り直す必要があります
  • パスワードは OS のキーチェーンに保存されます Windows 資格情報マネージャー · macOS キーチェーン · Linux libsecret。キーチェーンが使えない環境では、プロファイルの env に平文で保存し、警告を表示します

3 層の防御

本番環境に接続する前に、まず最初に確認される部分です。ドキュメントではなく、コードで強制されます

L1a

行抽出のブロック

Claude Code の PreToolUse フックです。プロファイルの blocklistProfile に基づき、機密テーブルに対する GetTableContents · GetSqlQuery を拒否します

L1b

tier による変更のブロック

Claude Code の PreToolUse フックです。呼び出しのたびにアクティブなプロファイルの SAP_TIER を読み直し、QA・PRD での変更を防ぎます。状態は保持しません

L2

MCP サーバー自体のガード

回避できない層です。フックが外れていたり設定を誤っていたりしても、abap-mcp-adt-powerup 内部のガードが常に動作します

L1 フックは IO・パースエラー時には通過させ、L2 の MCP ガードは常に有効です。推奨デフォルトは L1a strict、MCP サーバーのブロックリスト standard です
